# RFC 0002 — Spec v1 (Layout & Semantics)

Status: Draft
Owner: Core

Summary
- Define spec files, stable paths, and patch conventions for v1.

Files
- `spec/ui.json`
- `spec/logic.json`
- `spec/data.json`
- `spec/theme.json`
- `spec/tests.json`
- `spec/overlays.json`
- `spec/analysis.json`
- `spec/meta.json` (audit, versioning)

Patch Conventions
- Use RFC6902 (add/replace/remove).
- JSON Pointer path starts with `/` and targets the in-memory spec tree.
- Proposals reference a single scope (one file) per ticket.

Paths & Policies
- Geometry/layout in `ui.json`: only `@frameforge/ext-ui` may propose changes.
- Agents & Policies in `logic.json`: toggles emit diffs; approvals gate application.
- RAG config: `data.json.rag.indices[]` and `logic.json.agents[].rag` (indices, reranker, topK). UI should block attach when offline.

Audit & Idempotency
- Kernel appends audit entries to `meta.audit` on apply.
- Include `idempotencyKey` when submitting proposals to avoid duplicates.

Validation
- Scripts validate proposal artifacts and manifests (warn-only in CI to allow incremental fixes).
- Future work: schema validation per file with AJV.

Dev & Prod
- Dev endpoints (`/__ff/*`) are explicitly gated by `VITE_EXPOSE_DEV=1`.
- Prod loads extensions from built paths; no dev writers are exposed.

Security
- Proposal-only writes; no direct spec file writes from the browser.
- GitHub and external APIs are accessed via a broker/proxy; PAT scopes minimal and rotated.
- Rate limits and backoff are enforced in the broker per tool.
